# 汉语脑电信号分类软件系统

北京交通大学 · 大学生创新训练计划
**《基于深度学习的汉语脑电信号建模与分析研究》** —— 项目预期成果之"汉语脑电信号分类软件系统"

一套完整的脑电分类流水线：**数据加载 → 预处理 → 特征提取 → 模型训练 → 性能评估 → 可视化报告**，
提供图形界面（PyQt5）与命令行两种使用方式。

## 一分钟上手

```bat
:: 1. 装依赖（只需一次）
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
pip install torch --index-url https://download.pytorch.org/whl/cpu

:: 2. 双击运行
run.bat
```

没装环境也能先看效果 —— 界面打开后点 **① 数据 → 生成数据**，再依次到
**③ 训练 → 开始训练**，几分钟内就能看到完整结果。

## 这个系统能做什么

| 能力 | 说明 |
|---|---|
| **两类分类模型** | STFT-SVM 基线（传统方法）与 ShallowConvNet（深度学习），同一套评估口径下对比 |
| **完整的预处理链** | 带通滤波、50 Hz 工频陷波、重参考、基线校正、伪迹剔除、逐通道标准化，参数全部可调 |
| **严格的评估方法** | 分层 K 折交叉验证、留一受试者评估、**置换检验**（阴性对照，证明无数据泄漏） |
| **信息量化的结论** | 准确率 / 宏 F1 / Cohen's κ / 混淆矩阵 / 逐类精确率召回率，而非只报一个准确率 |
| **信噪比扫描** | 系统性回答"多难的数据下深度模型才跑赢传统方法" —— 用真实标定，不是拍脑袋定参数 |
| **逐折配对比较** | 同一折上对比两个模型，避免"均值 ± 标准差"掩盖真实的差距 |
| **一键 HTML 报告** | 单文件、图片内嵌，直接发给老师即可打开 |
| **真实数据接口** | 覆盖 EGI `.mff`、BrainVision `.vhdr`、EDF/BDF、EEGLAB `.set`、FIF；支持与 PsychoPy 打标日志对齐 |

## 环境要求

- **Python 3.13**（本项目在 anaconda `base` 环境，`D:\anaconda\python.exe` 3.13.9 上验证通过）

## 使用方式

### 图形界面

```bat
run.bat
```

或 `python -m cneeg gui`。界面按使用顺序分成五页：

| 页 | 做什么 | 关键点 |
|---|---|---|
| **① 数据** | 生成仿真数据 / 导入真实脑电文件 | 预设、受试者数、试次数、**信噪比**、随机种子都可调，固定种子结果完全可复现 |
| **② 预处理** | 调滤波/参考/窗口/伪迹阈值，即时看前后对比 | 上图原始、下图处理后；剔除伪迹会让试次变少，属正常 |
| **③ 训练** | 选 SVM / CNN，调超参，后台训练 | 界面不卡死；进度条下方实时画验证集 F1 曲线；可随时取消 |
| **④ 评估** | 混淆矩阵、指标汇总、SVM vs CNN 对比、导出报告 | 两个模型都训完后可看对比图与显著性 |
| **⑤ 推理** | 载入数据 → 逐试次预测 + 置信度 + 空间拓扑 | 用的是交叉验证后在全量数据上重训的模型 |

> 训练在后台线程运行，可以随时切页、取消。CPU 上 SVM 约 1 分钟，CNN 约 5–15 分钟。

### 命令行

整条流水线不需要点界面也能一键复现 —— 答辩演示、老师验收、批量跑实验时用它。

```bat
:: 生成数据
python -m cneeg gen-data

:: 训练单个模型
python -m cneeg train --model svm
python -m cneeg train --model cnn --permutation     :: 附加置换检验

:: 留一受试者评估（更严格：测试受试者训练时完全没见过）
python -m cneeg train --model svm --group

:: SVM vs CNN 对比 + 出 HTML 报告
python -m cneeg compare

:: 信噪比扫描 —— 找出 CNN 何时跑赢 SVM
python -m cneeg sweep --snrs -12 -8 -4 0 4 8

:: 存下模型（infer 要用；普通训练不落盘）
python -m cneeg train --model svm --save-model

:: 用真实脑电文件推理
python -m cneeg infer --file "D:\data\被试01.mff"

:: 打开图形界面（不带子命令时也是这个）
python -m cneeg gui
```

**覆盖任意配置项**（`--set 键=值`，可重复，放在子命令前后都行）：

```bat
python -m cneeg train --model cnn --set model.cnn.n_epochs=200 --set seed=7
python -m cneeg gen-data --set data.synthetic.snr_db=-6 --set data.synthetic.n_subjects=10
```

一键跑完整验收流程：`run_cli.bat`

## 接入实验室真实数据

真实数据到位后**只需改一行配置**，其余流程完全不动：

```yaml
# configs/default.yaml
data:
  source: "file"                        # synthetic → file
  file:
    path: "D:/data/被试01.mff"          # 指向你的脑电文件
```

或者在命令行直接用 `--file`：

```bat
python -m cneeg train --model cnn --file "D:/data/被试01.mff"
```

**支持的格式**：`.mff`（EGI NetStation，你实验室用的就是它）、`.vhdr`、`.edf`、
`.bdf`、`.cnt`、`.set`、`.fif`。

**与 PsychoPy 打标对齐**：如果你的记录里没有内嵌事件轨，系统可以读
`脑电实验/data/trials_*.csv`（含 `word_onset_s` 列）来还原每个试次的起始时刻。

**多受试者**：把多个文件放进一个目录，配合 `subject` 字段即可做跨受试者评估 ——
这是更接近真实论文设定的评估方式，结果通常明显低于普通交叉验证，
两者之差本身就说明模型学到的是任务相关成分还是个体特征。

## 核心实验结论

> 下列数字全部来自本仓库中可直接复现的运行产物，不是估计值。
> 原始数据：`scripts/snr_sweep.csv`、`scripts/compare2.log`、
> `data/reports/results_compare_20261007_085113.json`（含逐折指标与置换零分布）。

**一句话结论：决定 CNN 能否跑赢传统方法的不是模型，而是数据量。**
数据量足够时 CNN 五折全胜（66.8% vs 58.9%）；数据量减半后两者打平；
信噪比再降下去，两个模型都退回随机水平。详见下文两张表的对照。

### 主实验：四声调分类，5 折交叉验证

仿真数据 6 受试者 × 60 试次/类 × 4 类（共 1440 试次，伪迹剔除后 1302 试次），
信噪比 +4 dB，随机水平 **25%**，两种模型跑**完全相同的折划分**：

| 模型 | 准确率 | 宏平均 F1 | Cohen's κ | 特征维度 | 耗时 |
|---|---:|---:|---:|---:|---:|
| SVM（STFT + 分频带功率） | 58.9% ± 1.8% | 0.590 ± 0.017 | 0.452 | 2848 | 89 s |
| CNN（ShallowConvNet） | **66.8% ± 3.0%** | **0.662 ± 0.032** | **0.558** | 原始波形 | 431 s |

**逐折配对比较**（同一折上两个模型面对同一批数据，这比比均值可靠得多）：

| 折 | 1 | 2 | 3 | 4 | 5 | 平均 |
|---|---:|---:|---:|---:|---:|---:|
| SVM | 57.1% | 57.5% | 61.2% | 57.7% | 61.2% | 58.9% |
| CNN | 67.4% | 60.9% | 68.8% | 67.7% | 69.2% | 66.8% |
| 差 | +10.3 | +3.4 | +7.7 | +10.0 | +8.1 | **+7.9** |

**CNN 五折全胜**，平均领先 7.9 个百分点。SVM 的 58.9% 在三次独立运行中逐位复现。

> 顺带一提：CNN 的逐折标准差（3.0%）是 SVM（1.8%）的 1.7 倍 ——
> 平均更好，但**对数据划分更敏感**。

### 置换检验（阴性对照）

把标签随机打乱后重跑 20 次，得到零分布：

| 项目 | 数值 |
|---|---|
| 零分布（打乱标签） | 26.1% ± 3.3% |
| 实际观测 | 58.9% |
| 经验 p 值 | 0.048 |

零分布紧贴随机水平 25%，说明**流水线没有数据泄漏** —— 这是所有结果可信的前提。
p = 0.048 看起来"刚好显著"，但要注意：只跑 20 次置换时，p 值的理论下限就是
1/21 ≈ 0.048。也就是说 20 次里没有任何一次打乱后的结果达到观测值，这是该置换次数下
**能拿到的最好结果**，而非"勉强过关"。想要更小的 p 值，把 `train.n_permutations` 调大即可。

### 信噪比扫描 —— 本项目最有价值的实验

固定其余条件，只改信噪比重跑（4 受试者 × 40 试次/类 = 640 试次，伪迹剔除后约 572，
留出法 20% —— 即 `train.test_size` 的默认值，脚本 `scripts/calibrate_snr.py`）：

| 信噪比 | SVM | CNN | 观察 |
|---:|---:|---:|---|
| −12 dB | 33.0% | 28.7% | 两者都接近随机；CNN 更低 |
| −8 dB | 31.3% | 32.2% | 两者都接近随机 |
| −4 dB | 33.0% | 32.2% | 两者都接近随机 |
| 0 dB | 40.9% | 28.7% | SVM 开始脱离随机，CNN 仍未 |
| +4 dB | 50.4% | 53.9% | 两者都明显高于随机，CNN 略优 |

**怎么读这张表**：剔完伪迹剩约 572 试次，留出法 20% 意味着**测试集只有 115 个试次**，
准确率的标准误约 **4.0%**（p = 0.25 附近）到 **4.7%**（p = 0.5），
所以**相差 8 个百分点以内都不能当回事**。能站得住的结论有两条 ——

1. **信噪比是决定性因素**。同一对模型，从 −12 dB 到 +4 dB，SVM 从 33.0% 升到 50.4%、
   CNN 从 28.7% 升到 53.9% —— 提升 17～25 个百分点，**超出随机水平的部分扩大了三倍以上**
   （SVM 从 +8.0 到 +25.4 个百分点，CNN 从 +3.7 到 +28.9 个百分点）。
   讨论"深度模型好不好"而不交代信噪比，是没有意义的。
2. **低信噪比下两者都不行，且 CNN 更差**。−12 ~ −4 dB 区间 CNN 停在
   28.7%–32.2%，几乎不随信噪比改善而变化；SVM 依靠有先验设计的频带功率特征，
   退化得更平缓。

### 把两张表放在一起看：结论是"看数据量"

信噪比扫描的 640 试次和主实验的 1302 试次，**信噪比同为 +4 dB**，
差别只在数据量。结果却完全不同：

| 数据量 | 每折训练量 | SVM | CNN | 结论 |
|---|---:|---:|---:|---|
| 640 试次（留出法） | ~457 | 50.4% | 53.9% | 打平（差距在标准误内） |
| 1302 试次（5 折） | ~1041 | 58.9% | **66.8%** | **CNN 五折全胜** |

> **决定 CNN 能否发挥优势的不是模型本身，而是数据量。**
> 数据量不够时，CNN 要自己从数据里学滤波器，学不过 SVM 那套有先验设计的特征；
> 数据量上来之后，端到端学习的优势就体现出来了。
>
> 这与 Schirrmeister et al. (2017) 的方向一致，但**这次的证据来自我们自己的实验**，
> 不是转引文献 —— 数据量翻倍，CNN 从"打平"变成"全胜"。

> ⚠ **一个必须说清的局限**：这两行来自**两套不同的实验协议**（留出法 vs 交叉验证），
> 数据量和评估方式同时变了。所以"数据量是关键"是对两个观测点的**合理解释，
> 不是受控实验的结论** —— 两个点也画不出趋势。要真正验证它，需要固定其余一切、
> 只改数据量做一次扫描，这已列入下一步工作。
>
> 真实数据接入后同样需要重新验证：真实脑电的个体差异远比仿真数据大。

## 重要声明：关于仿真数据

> ⚠ **本系统默认使用程序生成的仿真脑电数据。**

**为什么**：实验室的真实采集尚未开始，而软件流水线、模型对比方法、评估指标
都可以先在可控的仿真数据上验证。这样等真数据到手，直接换数据源即可，
软件本身不需要重写。

**仿真数据能证明什么**：软件流水线是通的、模型能学到东西、评估方法没有数据泄漏、
信噪比与分类性能的关系符合预期。

**仿真数据不能证明什么**：任何关于**真实汉语脑电**的结论。仿真数据的类别差异是
我们按先验写进去的模板，模型学到它们是理所当然的 —— 这不是科学发现。

**系统如何处理这一点**：

- 所有图表右下角带"仿真数据"水印
- HTML 报告顶部显示**红色警示横幅**（真实数据则为绿色）
- 终端输出、数据摘要中均显式标注
- 本文档与 `docs/技术文档.md` 中明确说明

真实数据接入后重新运行，届时结论才具科学意义。

## 常见问题

**Q：报错 `ModuleNotFoundError: No module named 'torch'`**
A：装 CPU 版 PyTorch：`pip install torch --index-url https://download.pytorch.org/whl/cpu`

**Q：报错 `ModuleNotFoundError: No module named 'mne'`**
A：`pip install mne`。只跑仿真数据其实用不到 mne，但导入链会检查它。

**Q：程序启动后窗口是空白的 / 中文显示成方框**
A：图表中文依赖系统字体（微软雅黑 / 黑体）。Windows 一般自带；
若显示成方块，检查 `C:\Windows\Fonts` 下是否存在 `msyh.ttc`。

**Q：训练时界面"未响应"**
A：不会。所有耗时操作都在后台线程里跑。如果确实卡住了，多半是数据规模过大，
先减少受试者数或试次数试一下。

**Q：CNN 准确率只有 25%（等于随机）**
A：多半是信噪比太低。默认配置的 `snr_db: 4.0` 是**实测标定**过的取值
（见 `scripts/calibrate_snr.py`），两个模型都能明显高于随机。
若你手动调低了它，CNN 会在低信噪比下先崩掉 —— 这正是上面那条核心结论。

**Q：`--set` 写的参数好像没生效**
A：键名写错会被明确报错（不会静默忽略）。可用键见 `configs/default.yaml`，
形如 `data.synthetic.snr_db`、`model.cnn.lr`、`train.n_splits`。

**Q：PyTorch 报 `OMP: Error #15`**
A：已在 `src/cneeg/__init__.py` 里设置 `KMP_DUPLICATE_LIB_OK`，
这是 anaconda MKL 与 pip 版 PyTorch 的 OpenMP 运行库冲突，属已知问题、不影响结果。
